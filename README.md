# LogTime

> **Time is linear. Perception is not.**

LogTime 是一个以**非线性节奏呈现时间**的计时器。

真实时间始终匀速流逝，而 LogTime 通过数学模型改变时间的视觉呈现，让同一段真实时间拥有不同的观看方式。

## 两种时间模型

LogTime 提供两种视觉模型：

### Model A · 启程

以对数函数构建：

$$
P_A(x)=\frac{\ln(1+2x)}{\ln3}
$$

视觉进度在开始阶段较快，随后逐渐放缓。

它像是从时间的起点出发，进度在最初迅速展开，之后逐渐趋于平缓。

### Model B · 抵达

以平方函数构建：

$$
P_B(x)=x^2
$$

视觉进度在开始阶段较慢，随着时间推移逐渐加快。

它将注意力更多地留向时间的后段，直到最终抵达终点。

两种模型描述的是同一段真实时间，只是选择了不同的非线性节奏。

---

## 视觉

LogTime 提供两种独立的视觉呈现方式：

* **Ring** — 圆环
* **Grid** — 方格

两种视觉使用相同的时间模型，但以不同的几何形式呈现。

圆环以连续的轨迹表现时间；Grid 则将进度离散为 **20 × 10，共 200 个格子**。

视觉形式可以随时切换，而不会改变任务本身的时间进度。

## 时间与视觉

LogTime 将实际经过的时间首先表示为：

$$
x=\frac{t}{T}
$$

其中 \(t\) 为已经经过的真实时间，\(T\) 为任务总时长。

随后，根据用户选择的模型计算视觉进度 \(P(x)\)。

因此：

$$
\text{真实时间} \rightarrow \text{数学模型} \rightarrow \text{视觉进度}
$$

**真实时间从未被改变。**

改变的只是它被呈现的方式。

---

## 完成

当任务达到 100% 时，计时停止并停留在完成状态。

LogTime 会以一个简短的 Emoji 庆祝作为结束反馈，并允许用户生成当前画面的图片。

完成并不是一个需要被反复强调的成就，而只是时间自然抵达终点的那一刻。

---

## 数据

LogTime 是一个纯前端网页。

任务状态与显示设置保存在浏览器的 `localStorage` 中，不需要注册账号，也不需要后端服务器。

目前不会将任务数据上传至云端。

---

## 技术

LogTime 使用：

* HTML
* CSS
* Vanilla JavaScript
* Canvas API
* CSS Grid
* localStorage
* html2canvas

圆环由 Canvas 绘制，Grid 使用 CSS Grid 构建；时间计算以真实时间戳为基础，而不是简单依赖计时器累加。

项目目前保持为轻量的单页网页结构，不依赖 React、Vue 等前端框架。

## 项目理念

LogTime 并不试图让时间变快或变慢。

它只是提出一个简单的问题：

> **如果真实时间始终匀速流逝，我们能不能换一种方式去看它？**

从心理感知，到数学模型，再到视觉呈现，LogTime 将时间变成了一个可以被观看、被体验的对象。

**Time is linear.
Perception is not.**
